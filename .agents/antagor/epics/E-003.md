## Problem

ADR-0001 replaced the architecture: the gateway owns access, OAuth subscriptions, quotas, fallback, journal and price. llmkit still carries its own database layer, journal, response cache, price table, model-chain retries, subscription transports and HTTP proxy, and every one of them is now a second, poorer copy of what the gateway does. The CLI still documents LiteLLM-era ideas, and two loose documents (a specification and a plan) are not doc kinds.

## Goal

llm and the Python API reach models only through the 9router gateway: a typed API, media wrappers and a CLI every agent can drive by --help and --json. llmkit keeps code only — no database, journal, response cache, price table, subscription transports or proxy of its own. antagor layout check is clean: the specification and the plan are gone, their content lives in living docs, ADRs and ideas.

## Acceptance (Given–When–Then)

- Given a routing with one openai_compatible provider pointing at the gateway, When lm ask, lm generate and lm ask_many run, Then the answer, its model, provider and cost come from the gateway response and no LiteLLM or Instructor code runs.
- Given the installed package, When its dependencies and imports are checked, Then LiteLLM, Instructor, SQLAlchemy, Alembic, psycopg and the subscription transports are gone and import llmkit stays under 300 ms.
- Given a running gateway, When lm doctor --json and lm describe --json run, Then they name the gateway, its reachability and the whole wrapped surface, and every command has --help with an Example line and --json.
- Given the repository, When antagor layout check and antagor memory-check run, Then neither reports anything to fix.

## Implementation decisions

- HTTP client: httpx only. LiteLLM goes: the gateway does provider choice and fallback, LiteLLM reshapes the response fields we need (usage.cost, provider, model) and does not cover the media endpoints.
- JSON by schema: response_format json_schema plus pydantic validation and a bounded retry with the validation error text. Instructor goes with LiteLLM.
- Always stream: the gateway journals only streamed calls, so llmkit always sends stream true and assembles the answer from JSON or SSE (data: [DONE]).
- Cost, served model and provider are read from the gateway answer; they are optional because subscription providers return no provider and cost 0.
- No own database: no journal, cache, price table, migrations, LLMKIT_DATABASE_URL or db commands. Spend is read from the gateway journal (SQLite, read-only) and a consumer is told apart by its gateway API key.
- Routing keeps one openai_compatible entry with the gateway base URL and the name of an environment variable holding its key; model names are passed verbatim as written in the gateway settings.

## Out of scope

- Moving other repositories (antagor, intentree, windmill, wordpress-bulk-editor) to the new API and to the gateway journal; that is the Human business outside this repository.
- Changing Antagor itself; a gap only llmkit has is worked around here.
