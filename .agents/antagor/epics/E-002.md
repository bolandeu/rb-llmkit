## Problem

Two legacy docs mix kinds: docs/prd.md is a specification (v1 spec, partly overtaken by code and by ADR-0001) and docs/backlog.md is a plan (items partly done, partly contradicted by ADR-0001). Antagor refuses a new .md outside the four doc kinds and layout check keeps both on the 'to sort' list, so the project cannot add documents.

## Goal

Every tracked .md has one doc kind; `antagor layout check` reports nothing to sort; no product decision is lost: each section of docs/prd.md and docs/backlog.md is either in a living doc, an ADR, a research record, an idea, or dropped with the Human's yes.

## Acceptance (Given–When–Then)

- Given docs/prd.md and docs/backlog.md, When the epic is done, Then both files are gone and `antagor layout check` prints no "docs to sort".
- Given any section of either file, When the work is accepted, Then the acceptance report names its destination: a living doc (README.md, CONTEXT.md, docs/architecture.md, docs/cli-conventions.md, docs/testing.md), an ADR, a research record, an idea (`antagor idea add`) or a drop with the Human's reason.
- Given a dropped section, When the epic is accepted, Then the Human saw the dropped text and the reason before accepting (check: manual).

## Implementation decisions

- Content moves to the living docs and ADRs; what the docs put off becomes ideas, one per item; a file that is none of the doc kinds is deleted, not renamed.

## Out of scope

- Code or behaviour changes; implementing ADR-0001 (its own epic later, tracked by an idea).
