# Одна база журнала для всех инструментов, общая PostgreSQL или локальная SQLite

Восстановлено по истории и коду (подтверждение Человека ожидается).

Журнал вызовов, кэш ответов и ключи связи живут в одной базе под именами
`llmkit_*`: общая PostgreSQL, если задан `LLMKIT_DATABASE_URL` (серверы), иначе
локальная SQLite в каталоге данных пользователя (Mac). Другие инструменты и
Directus читают только представления `llmkit_v1_*`; колонки представления не
меняются и не удаляются, новая форма получает `_v2_` рядом.

Почему: расходы делят несколько инструментов и процессов (antagor, wp-bulk, `llm`),
их надо видеть одной таблицей, а не собирать из файлов; потребителю нужен
стабильный контракт колонок, поэтому читает он представление, а не таблицу.

- **Status**: accepted
- **Отвергнуто**: кэш LiteLLM (diskcache) — непрозрачный ключ и отдельный файл,
  нет учёта попаданий по меткам; суммирование расходов по файлам SQLite каждого
  инструмента — нет общей картины.
- **Следствие**: каждая миграция совместима с предыдущим релизом (expand/contract);
  PostgreSQL мигрирует только `llm db upgrade` выпущенной версией; переход между
  базами — вручную, `llm db import-sqlite`.
