# Routing — данные, а не настройки llmkit

Восстановлено по истории и коду (подтверждение Человека ожидается).

С 0.8.0 у llmkit нет встроенных провайдеров, уровней и цен: провайдеры, цепочки
моделей и цены приходят данными в формате routing v1 (`routing.json`). Контракт
формата — `src/llmkit/contracts/routing-v1.schema.json` с векторами, он публичный
и лежит в колесе, поэтому потребитель и llmkit проверяют одно и то же. `config.toml`
версий до 0.8 не читается: старый файл переносится `llm routing import`.

Почему: настройки и цены меняются чаще кода; данные можно положить в файл, отдать
потребителю и проверить схемой, а секретов в routing нет — только имя переменной
с ключом.

- **Status**: accepted
- **Отвергнуто**: конфиг-файл llmkit (`config.toml`, читался до 0.8) — правка
  требует релиза библиотеки и не проверяется внешним контрактом.
- **Следствие**: библиотека env не читает; путь к routing выбирает CLI
  (`--routing` → `LLMKIT_ROUTING_FILE` → файл в каталоге настроек пользователя).
