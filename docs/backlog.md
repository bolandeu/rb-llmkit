## Фаза 3 — перевод antagor и intentree на llmkit

Первым — antagor (задание готово, `docs/phase3-antagor.md`): 36 файлов на
`generate()`. Ключи из `data/.env` продолжат работать (имена env совпадают
со стандартными именами llmkit), плюс связка `llmkit:*`. Затем —
windmill-скрипты и одноразовые клиенты в `tasks/*`.

Дальше — intentree: адаптер `Task(stage, subject_type, subject_id, …)` →
`llmkit.Task(tags={tool:"intentree", stage, subject_type, niche})`,
`LlmRunner` поверх `ask_many_sync`, `LlmStats` из `kit.stats`; журнал решений
остаётся в intentree. Удалить `providers/llm.py` и таблицу `llm_cache`.

## Внешний шлюз доступа (9router) вместо своего кода

Решение 2026-10-08: не писать в llmkit то, что уже умеет готовый шлюз
[9router](https://github.com/decolua/9router) (Node.js, OpenAI-совместимый
прокси на `localhost:20128/v1`, работает на macOS и Linux). Разделение слоёв:
шлюз — доступ (OAuth-подписки Claude Code/Codex/Copilot/Cursor/Kiro, ротация
аккаунтов, квоты, 40+ провайдеров, трансляция форматов); llmkit — логика
(схемы, кэш, шаблоны, учёт по меткам, бюджеты, цепочки).

- **Подключение** — без кода: провайдер `openai_compatible` в routing с
  `base_url: http://localhost:20128/v1`. Проверить вживую, что приходит в `usage`.
- **Модели — конкретные, не комбо 9router**: комбо скрывает, какая модель
  ответила, — ломаются кэш (ключ по модели) и учёт. Фолбэк — цепочкой llmkit.
- **Стоимость**: `usage.cost` от шлюза не ожидается → `price_table` для
  провайдера; подписки — 0 с `billable=false`.
- **Не делать своими силами**, пока шлюз закрывает задачу: новые транспорты
  подписок (сверх ChatGPT/Claude), ротацию аккаунтов, прокси `llm serve`
  (фаза 4 — пересмотреть).
- **Безопасность**: CVE-2026-49352 (зашитый JWT-секрет, ≤ 0.4.44/0.4.45) и
  CVE-2026-49353 (обход local-only через заголовки за прокси/туннелем).
  Ставить свежую версию, задавать `JWT_SECRET`, слушать только localhost, не
  выставлять наружу — в шлюзе токены всех подписок.
- **Альтернатива** — форк OmniRoute (больше провайдеров, стратегии, семантический
  кэш): тяжелее и дублирует llmkit; по отзывам унаследовал секрет по умолчанию.

## Не привязано к конкретной фазе

### Бюджеты по параметрам

Сейчас: один дневной лимит `budget.daily_usd` (20 $), только предупреждение.

План:

- **Лимиты по метке** — `[budget.tags]` с ключами вида `"tool=intentree" = 2.0`, `"niche=ved" = 1.0`: ядро уже умеет, но по умолчанию выключено и в шаблоне закомментировано. Включить, когда появится реальная потребность делить расход между инструментами и нишами.
- **Лимиты по уровню и провайдеру** — `"level=strong" = 5.0`, `"provider=openrouter" = 10.0`: та же механика, метки `level` и `provider` ядро проставляет само.
- **Периоды** — кроме дня: неделя, месяц, «на задачу» (`Task.budget_usd`, лимит на одну пачку `ask_many`).
- **Реакция на превышение** — сейчас только предупреждение (решение пользователя). Опции на будущее, по выбору в конфиге: понижение уровня на дешёвую цепочку, отказ с `BudgetExceeded`.
- **CLI** — `llm budget show/set`, а `llm cost` показывает остаток по каждому лимиту.

### Ядро

- **Негативный кэш**: стабильно падающая первая модель цепочки сейчас пробуется заново при каждом вызове. Запоминать провал на короткий срок (cooldown по модели, как в LiteLLM Router).
- **Сентинел для `default`**: сейчас `default=None` неотличим от «default не задан», вернуть осмысленный `None` нельзя.
- **Офлайн-тест пути Instructor** с настоящим `litellm.ModelResponse` и `tool_calls`.
- **Streaming** в `generate` и CLI (`--stream`), затем в прокси — PRD §12 относит к «вне v1».
- **Embeddings**: уровень `embed`, `kit.embed(texts)` через `litellm.aembedding`, тот же учёт — PRD §12 «вне v1».
- **Батч-API провайдеров** (OpenAI Batch, Anthropic Batches) для пачек, где не важна скорость: вдвое дешевле — PRD §12 «вне v1».
- **Прогресс и возобновление пачек**: `ask_many` с чекпоинтом по `Task.id`, чтобы возобновление не зависело только от кэша.

### Инструменты

- `llm cost --export csv/json` и отчёт за период по дням.
- `llm doctor`: проверка ключей, доступности провайдеров и цен моделей одной командой.
- Цены моделей Ollama Cloud в шаблоне конфига (LiteLLM их не знает), обновление таблицы цен.
- `llm models` падает с exit 2 на уровне с неизвестным провайдером в цепочке — можно смягчить (сейчас это `ConfigError`, есть смысл показывать как предупреждение по конкретному уровню, а не рвать всю команду).

### Известный технический долг

- `usage.py`: подавленное предупреждение линтера `# noqa: S608` на SQL-запросе отчёта — не убрать, пока `json_extract(tags, '$.tool')` собирается конкатенацией; имена меток валидируются регуляркой `TAG_NAME_RE`, но при ревизии стоит пересмотреть, нельзя ли параметризовать путь целиком.
- Документация путей `platformdirs` (README/PRD) не разделяла явно macOS (`~/Library/Application Support`) и Linux (`~/.config`, XDG) — см. PRD §3.

### Процесс сессий

Из сессии 2026-09-21 (перезапускалась из-за тяжёлого контекста): отчёты
сабагентов просить ≤ 15 строк; полное ревью — только на ядро, дальше
точечные проверки лидом; не делать второй круг ревью после правок.
