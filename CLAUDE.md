# llmkit — инструкция для агента

Библиотека-слой над LLM-провайдерами: цепочки моделей, кэш, учёт расходов.
Спецификация — `SPEC.md`, она главнее этого файла. Реализованы фазы 0–2
(ядро и CLI); прокси (`src/llmkit/serve/`) — фаза 4, его пока нет.

## Структура

```
src/llmkit/
  config.py     модели конфига, загрузка и слияние слоёв
  keys.py       ключи: конфиг → env → связка ключей ОС
  providers.py  провайдер + модель → аргументы LiteLLM
  chain.py      цепочки, классификация ошибок, ретраи и backoff
  cache.py      SQLite-кэш ответов
  usage.py      SQLite-журнал вызовов, отчёты, бюджеты
  core.py       LlmKit: ask / generate / ask_many и sync-обёртки
  errors.py     исключения
  _sync.py      запуск корутины из синхронного кода
  cli/          команда `llm`: output.py (конверт, guard), runtime.py (фабрика
                ядра, её подменяют тесты), модуль на группу команд, main.py
scripts/smoke.py  реальные вызовы провайдеров (фаза 0)
docs/             результаты smoke
```

## Команды

```bash
uv sync
uv run pytest -q
uv run ruff check src tests
uv run python -X importtime -c "import llmkit" 2>&1 | tail -1   # должно быть < 300 мс
```

## Конвенции

- `litellm`, `instructor` и `keyring` импортируются **лениво**, внутри функций
  пути вызова: `import llmkit` обязан оставаться быстрым (сейчас ~80 мс).
- Тесты сети не касаются: вызов модели подменяется через `LlmKit(completion=...)`,
  конфиг/кэш/журнал — во временных каталогах (фикстура `isolated` в
  `tests/conftest.py`).
- Классификация ошибок идёт по **имени класса** исключения (`chain.py`), чтобы
  модуль не тянул litellm на импорте; `classify()` возвращает None для чужих
  исключений — их ядро пробрасывает, а не маскирует под ошибку провайдера.
- Ключи не логируются и не пишутся на диск; `.env`-файлы не используются.
- Комментарии и докстринги — по-русски, короткие. Ruff: `line-length = 120`,
  набор правил в `pyproject.toml`.
- CLI: новые группы команд создаются через `output.group(...)` (пустой вызов
  печатает help и выходит с 0), тело команды — внутри `with guard(ctx)`,
  результат — через `emit(ctx, payload, render)`; коды выхода — из
  `conventions.md` cli-builder (0/1/2/3/5), см. `cli/output.py`.
- Зависимости сверх раздела 2 SPEC не добавлять.
